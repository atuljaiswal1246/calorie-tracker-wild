# M4 — QUIET: the app is gentle by accident, now by construction

**Landed 2026-09-27.** `test/quiet_copy_test.dart` (+2 tests, suite now 221).

## What the audit found: the app is already clean

I scanned every user-facing string in `lib/`. 27 candidates matched a
shame/pressure pattern; reading all 27, **none of them shame the user**:

- 20 are developer messages — `'Image copy failed'`, `'Purchase failed'`,
  `'Widget push failed'` — or exception text.
- 2 are parked Asha lines (`Features.asha = false`) that *name* guilt in order
  to dissolve it.
- The rest are genuinely gentle: `"Missed yesterday? No worries — one quick log
  gets you back on track today"`, and the streak freeze sold as `"covers one
  missed day so a rest day never breaks you"`.

Notification opt-out is real, not decorative: Water reminders default **on**,
Meal reminders default **off** (`mealRemindersEnabled => … ?? false`), and both
toggles persist and call `cancelAll()` / `scheduleAll()`. The second test locks
that default in, because a health app that nags by default loses the person it
is meant to help.

## Why a test, though

The app is gentle **by accident**. Nothing stopped it: a well-meaning copy
change in any screen could have shipped "You missed yesterday" or "Try harder"
and the suite would have stayed green. So the property is now a **check**, not
a promise.

**Proof the check bites.** Injecting `'You failed again. Try harder.'` into
`home_screen.dart` fails the test:

```
Shame/pressure copy found in 1 place(s).
      "You failed again. Try harder."
00:00 +1 -1: Some tests failed.
```

The file was then restored (`git diff` empty), and the full suite is green.

## Two things I got wrong in this pass, and the rule that came out of it

1. **I grepped for a notifications switch, found none, and nearly reported
   "there is no opt-off at all."** Wrong: the toggles exist, named
   `_toggleWater` / `_toggleMeal`, which my grep for `notif` missed. A grep is
   a hypothesis, not a finding.
2. **The guard flagged `"No food detected"` and I called it a clinical
   dead-end.** Wrong: `capture_screen.dart` puts an **"Enter manually"** button
   and a retry directly beneath that text, so the user is never stuck. I had
   also written it into the *banned shame* list, which was the wrong rule
   entirely — a dead-end is a QUIET failure, not a shame failure. Removed it
   rather than leaving a wrong rule in place to satisfy a test.

Both are the same mistake as claiming a prompt fix was "proven" from one run:
**a conclusion reached without looking at the code that would prove it.**

## The rule, written down so it outlives me

> Before reporting a defect, open the file and read the lines around it.
> A pattern match is a hypothesis. Report what you read.

## Not done, deliberately

- No copy was changed. There was nothing to fix.
- No master "pause everything" switch was added: Meal reminders already default
  off, so the app is quiet on arrival and both categories are one tap away.
  A third switch would be one more row to explain.
